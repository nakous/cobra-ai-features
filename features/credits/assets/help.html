Credits System

The Credits System feature lets you grant, track and consume credits (points or currency) for any registered WordPress user. Credits can be typed (subscription, paid, free, coupon, gift, reward, discount, bonus), dated, and expired automatically. Every operation is logged in the plugin’s system log.

Key concepts

  • Credit record — one row in {prefix}cobra_credits with credit, consumed, status and optional expiration_date. Available amount = credit - consumed.
  • Status — pending, active, expired or deleted. Only active rows contribute to the user balance.
  • Credit type — logical category, consumed in the order defined by Settings → Type order.
  • Cached balance — stored in user meta _cobra_ai_credit_balance and kept in sync by CreditManager::update_user_balance().

Admin pages

  • Cobra AI → Credits (cobra-ai-credits-manager) — list, add, edit and delete credit records.
  • Cobra AI → Credits Settings (cobra-ai-credits) — configure types, display, expiration and notifications.
  • Users list — a Credits column shows the balance with a per-type breakdown and an Add Credit row action.
  • User profile — last credit movements and a quick link to the management page.

Adding credits

  1. From Users → All Users, click Add Credit next to a user, or go to Cobra AI → Credits → Add New.
  2. Pick the type, amount, start and optional expiration date, and a comment.
  3. The form is processed by CreditAdmin::handle_add_credit(), which calls Feature::add_credit() — a thin wrapper around CreditManager::add_credit(). The user balance and logs are updated automatically.

Bulk operations

In the users list, select several rows, pick Add Credits in the bulk action dropdown and submit. The selection is stored in a 15-minute transient (cobra_ai_bulk_credit_users_<user_id>) and then applied to every selected user when you confirm the form.

Editing and deleting

  • Edit updates the credit/consumed/status fields and refreshes the user balance when any of them change.
  • Delete is a soft delete — the status is set to deleted and the balance is recomputed. Historical rows are preserved for audit.

Expiration & cron

A daily scheduled task runs CreditCron::run_expiration_check(), which flips expired rows to expired, refreshes the affected balances and fires cobra_ai_credit_expired for each record. When Enable expiration notice is on, users receive an email.

Admins can trigger the job manually from the Credits page using the Run now control — the call is nonce-protected via cobra_ai_run_cron_expiration_check.

Settings overview

  • General — enabled credit types, unit (points / currency), display name and symbol, and the consumption order.
  • Display — show credits in profile, show in users list, history rows per page.
  • Expiration — default duration in days, grace period, auto-expire toggle.
  • Notifications — enable expiration notices, how many days before expiry, and a custom email template.

Programmatic API

$feature = cobra_ai()->get_feature('credits');

// Add credits to a user
$credit_id = $feature->add_credit(
    $user_id,
    100.0,
    'paid',
    'Order #1234',
    '2026-12-31 23:59:59'
);

// Read balance
$total = $feature->get_user_credit_total($user_id);

// Per-type breakdown
$types = $feature->get_user_credit_types($user_id);

// History
$rows = $feature->get_user_credit_history($user_id, ['limit' => 20]);

// Consume (uses CreditManager directly)
$feature->manager->consume_credit($user_id, 10.0, ['reason' => 'api_call']);

Hooks

Actions

  • cobra_ai_credit_added ($credit_id, $data, $user_id)
  • cobra_ai_credit_consumed (...) — fired by the manager on consumption.
  • cobra_ai_credit_removed ($credit_id, $credit_row)
  • cobra_ai_credit_updated ($credit_id, $data)
  • cobra_ai_credit_expired ($credit_id)
  • cobra_ai_credit_status_updated ($credit_id, $new_status, $old_status)
  • cobra_ai_user_balance_updated ($user_id, $total)
  • cobra_ai_credits_transferred ($from_user_id, $to_user_id, $amount, $args)
  • cobra_ai_after_credit_added, cobra_ai_after_credit_removed, cobra_ai_after_credit_updated, cobra_ai_after_credit_expired — late hooks for notifications / integrations.

Filters

  • cobra_ai_credit_types — extend the list of selectable types.

Database

The feature uses a single table, {prefix}cobra_credits:

  • id, user_id, credit_type, type_id
  • credit, consumed, status
  • start_date, expiration_date
  • comment, meta (JSON-serialised extras)
  • created_at, updated_at

Indexes on user_id, credit_type and status keep the balance and listing queries fast on large installs.

Troubleshooting

  • Balance looks stale — call $feature->update_user_balance($user_id) or open the user’s profile; it forces a live recalculation.
  • Credits not expiring — confirm WP-cron is running and that Auto-expire is enabled in settings; you can also trigger the job manually from the Credits page.
  • Nothing happens on add — check Cobra AI → Dashboard → Logs; every failure is logged via cobra_ai_db()->log('error', ...).
